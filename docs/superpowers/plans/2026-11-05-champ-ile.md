# Champ « île » des articles — plan de mise en œuvre (partie 1/2 de la refonte en cartes)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajouter à chaque article une île facultative (Ngazidja, Ndzuani, Mwali, Maoré, Diaspora), saisissable dans le back-office, renseignée par la réécriture quotidienne et complétée une fois sur les articles déjà publiés — sans rien changer à l'affichage du site.

**Architecture:** Une colonne `articles.ile` nullable avec contrainte `check` (migration 0012, appliquée à la main par Yves dans l'éditeur SQL Supabase, comme 0011). Une liste canonique `build/lib/iles.mjs` (slug → libellé) sert au build et à la réécriture ; le back-office, servi tel quel au navigateur, garde sa propre copie testée contre la canonique. Un petit outil `scripts/iles/` exporte les articles publiés sans île et applique les îles choisies après validation d'Yves.

**Tech Stack:** Node ESM, `node:test`, `@supabase/supabase-js`, Postgres (Supabase).

**Spec:** `docs/superpowers/specs/2026-11-05-refonte-cartes-design.md` (sections « Données (Supabase) » et « Production »).

## Global Constraints

- Valeurs autorisées, exactement : `ngazidja`, `ndzuani`, `mwali`, `maore`, `diaspora` ; libellés : Ngazidja, Ndzuani, Mwali, Maoré, Diaspora.
- Colonne **nullable**, sans défaut : `null` = pas d'île (sujet national, international, ou doute). « En cas de doute, pas d'étiquette. »
- Aucun changement visible sur le site public dans ce plan (l'affichage vient avec le plan 2).
- Le remplissage des articles publiés est **montré à Yves avant écriture en base**.
- Migration rejouable (`if not exists`, `drop constraint if exists`), comme 0011.
- Le dépôt reste sur `main` en dehors des sessions de travail (la tâche planifiée de réécriture lance les scripts depuis la copie de travail) : travailler sur une branche `feat/champ-ile`, fusionner dans `main` seulement quand toute la chaîne est prête, et revenir sur `main` en fin de session.
- Ne jamais afficher les secrets de `.env`.

## Review Focus

- **Ordre de mise en ligne** : si `cli.mjs appliquer` écrit `ile` avant que la migration 0012 soit en base, l'update échoue et **aucun** brouillon n'est réécrit → la fusion dans `main` n'a lieu qu'après confirmation que la colonne existe (Task 5).
- **Sortie de réécriture sans champ `ile`** (anciens dossiers, oubli du rédacteur) : doit être traitée comme `null`, jamais comme une erreur bloquante → test dans Task 3.
- **Valeur inattendue** (`"Grande Comore"`, `"Anjouan"`, majuscules) : refusée par `controler` avec un message clair, et refusée en base par la contrainte → tests Tasks 1 et 3.
- **Article modifié dans le back-office sans toucher l'île** : la valeur existante est conservée (pas remise à `null`) → test dans Task 4.
- **Remplissage qui écraserait une île déjà saisie à la main** : `appliquer` du remplissage n'écrit que là où `ile is null` → test dans Task 5.
